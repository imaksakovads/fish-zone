> 1) ссылку на готовую статью-эталон, 2) закреплённую дизайн-систему,
> 3) воспроизводимый план/шаблон для следующих статей серии.

## 2. Закреплённая дизайн-система (фирменный стиль fish-zone.ru)

Не менять. Токены берём с реального сайта fish-zone.ru, не выдумываем.

- **Дисплейный шрифт:** Oswald (заголовки h1–h3, рубрики, цитаты).
- **Текстовый шрифт:** Manrope (тело, абзацы, списки).
- **Моно-шрифт:** для метаданных, подписей `figcaption`, цифровых статов, этикеток.
- **Акцент:** тёмно-синий (фирменный), используется экономно — не более 2 раз на экран.
- **Фон:** светлый «бумага» + тёмно-синие deep-блоки с градиентом и мотивом «водяных колец».
- **Радиусы:** ~18px, мягкие тени. Карточки скруглённые (не минимализм без рамок).
- **Все цвета — через `oklch()`-токены в `:root`; никаких raw-hex вне токенов.**
- Хром: тёмно-синий герой с хлебными крошками и статами, сайдбар-оглавление с прогрессом
  чтения, spec-таблица, FAQ-аккордеон, prev/next-карточки, CTA-полоса, футер.

## 3. План/шаблон для следующих статей серии

Каждую новую статью делать строго по этому рецепту.

### 3.1 Источник контента
- Брать исходный текст с fish-zone.ru (или у пользователя), извлекать **весь** контент целиком,
  не выбрасывать смысловые блоки. Никакого филлер-текста и выдуманных цифр.

### 3.2 Структура (повторяемый каркас)
1. Тёмно-синий герой: хлебные крошки, рубрика, H1, лид, дата + время чтения, герой-картинка.
2. Сайдбар-оглавление с прогрессом чтения и подсветкой текущего раздела (рабочий JS).
3. 8–9 глав контента, разбитых по смыслу (биология → сезоны → снасти → приманки → техника →
   таблица условий → катушка → FAQ).
4. 6 видов фирменных callout-блоков по ситуации:
   «Вывод за 30 секунд», «Опыт автора», «Частая ошибка», «Миф и правда», «Секрет», «Совет».
5. Spec-таблица «условия → снасть → тактика» (заполненная, не пустая).
6. Цитата-вывод, FAQ-аккордеон (Q1–Q4, рабочий), форма дайджеста, prev/next, футер.

### 3.3 Иллюстрации
- **Не менее 4–5 изображений в теле + герой** (длинная статья не живёт с 2 картинками).
- Реальные webp, скачанные в `assets/`, относительными путями; **никаких внешних URL-хотлинков**.
- Каждое изображение — в `<figure class="figure">` с `<figcaption>` (моно, muted).
- Нет подходящего фото в исходнике — либо искать в смежных руководствах сайта
  (гиды по катушке/спиннингу/щуке), либо генерировать через `media generate --surface image`
  (нужен настроенный ключ генерации), либо честный `.ph-img`-плейсхолдер. Не выдумывать.

### 3.4 Интеракции (обязательно рабочие)
- Прогресс чтения + подсветка активного раздела в оглавлении.
- Бургер-меню на мобильном. FAQ-аккордеон. Форма дайджеста.
- **Запрещено:** `scrollIntoView()` (ломает встроенный превью); `type="module"`; bare `const styles`.

### 3.5 Контракт и проверка (перед сдачей)
- `data-od-id` на каждой секции и повторяемых карточках (kebab-case).
- Контраст: обычный текст ≥4.5:1, крупный/иконки ≥3:1; hover НЕ уводит текст в muted.
- `:focus-visible`-кольцо на всех фокусируемых элементах.
- Адаптив: рефлоу ≤920px, без горизонтального скролла; тач-цели ≥44px.
- Без переполнений/наложений/обрезов текста; таблица в overflow-x на мобильном.
- Одна primary-кнопка на экран (остальные — вторичные/ghost).
- Палитра строго через токены; эмодзи не использовать как функциональные иконки (только инлайн-SVG).

## 4. Как desktop-агенту забрать работу

1. Дать ему этот файл (перетащить в чат или указать путь) **и** путь к статье-эталону.
2. Сказать: «Прочитай `handoff-brief.md` и файл `sudak-spinning-guide.html` как эталон,
   затем сделай следующую статью по этому плану: <тема>».
3. Агент сам прочитает эталон по абсолютному пути, скопирует структуру/стиль
   и применит план из §3 к новой теме.
